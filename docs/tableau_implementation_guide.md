# Tableau implementation guide

Run `scripts/export_tableau_data.py` after building the database. CSVs under `data/exports/tableau/` are distinct extracts; use each matching `.data_dictionary.md` for grain, units and missing-value behavior.

## Data model and dashboard suggestions

- Use `race_summary` for Grand Prix calendar coverage. Show a season line and a country/circuit highlight table.
- Use `driver_performance` for driver/season points, wins and podiums. Keep the row grain at one driver-season.
- Use `constructor_season_performance` for constructor trajectories. Connect on `constructor` and `year`; points are official constructor points.
- Use `circuit_country_summary` for host-country event counts.
- Use `reliability_summary` for season and official status labels. Calculate the completion rate as `SUM(classified_finishes) / SUM(entry_count)`, not the average of row percentages.
- Use `pit_stop_summary` for measured historical stops by season and `pit_stop_constructor_summary` for team comparisons. The latter excludes stop events whose race/driver result cannot be assigned to exactly one constructor.
- Use `tyre_strategy_summary` only as a standalone source-grain trend. Do not connect it directly to driver or constructor results without a separately verified key and grain.

Recommended workbook sheets: championship overview, driver head-to-head, constructor trajectory, global host-country calendar, reliability by status, observed tyre/weather laps, and pit-stop duration. Add season, driver, constructor and host-country filters only to extracts containing those fields. Tooltips should include year and source grain. Avoid a many-to-many relationship between lap-level tyre observations and race-result entries.
